# 叠条约束

2026-10-21。当前章节的作者走向约束，独立于 AI 重建的规划表单。

## 界面方向与交互契约

- Operate 模式：扩展现有 WPF 写作台，保留主题资源、Segoe UI / Microsoft YaHei UI、现有按钮与输入框样式；不改变应用视觉体系。
- AI 创作入口位于“本章规划”与“AI规划”之间。独立窗口约 1280×800，左右 3:2；左侧依次脉络、人物、戏份，右侧为同一进度带的彩色叠条。每组底部添加入口，右上横线打开领域专窗。
- 片段是可画框、移动和四边缩放的矩形。同条目可有多个分散片段，横轴共用 0–100% 本章叙事进度；纵向仅用于排布。数字输入和“添加片段”提供键盘操作路径。
- 右侧仅展示与定位；上下标签错位避让并带引线，长名称截断时可悬停看全名。默认脉络、人物、戏份由底到顶叠放，选中时临时置顶。选择片段或整个条目在两侧和专窗间同步，取消后恢复层级。
- 总窗口及专窗共享章节会话、草稿、选择、撤销历史和保存队列。文字框保留原生撤销。只读可浏览；失败保留草稿，关闭先保存。
- 0.3.7 显式绑定主窗退出条件，辅助 Alt+F4 只由当前窗口处理；当前数字输入在关闭判断前提交。关闭一个窗口不销毁共享会话，也不关闭其他窗口。

## 数据及服务接口

- `Chapter.stacked_constraints` 默认为 `{ "tracks": [] }`。条目保存 id、domain(thread/character/scene)、element_id、名称快照、weight(0.1–1，默认 0.5)、segments。
- 片段保存稳定 id、start/end(0–100)、top/bottom(0–100，仅布局)、directive。校验有限数值、正面积、ID 和同领域元素唯一性。空说明仍要求元素在对应区间出现或推进。
- `PUT /project/{project_id}/chapter/{n}/stacked-constraints` 在章节锁内合并保存、补入规划关联及设定快照，返回最新 Chapter。移除叠条不删除原规划或设定。
- SQLite 的 `stacked_constraints_json` 为可重复执行的增量迁移，作品章节元数据同步携带。新章不继承，AI 重新规划与复用原章节均保留。插入/删除章节前关闭并保存绑定章节号的窗口。
- 低于 0.1 的合法旧权重在持久化读取边界提升到 0.1，新 API 请求不做这种纠正而是拒绝。数据库读取、元数据导入和未完成保存日志均兼容，记录 `StackedWeightsMigrated`。章节 `stacked_weight_migration_pending` 记住一次性提示状态，`POST .../stacked-constraints/migration/ack` 确认后不再提示。
- 前端使用主窗口保存队列排序正文、规划及叠条写入；服务器保存时读最新章节。AI 上下文版本包含叠条语义摘要，晚到结果拒绝覆盖新语义；纯纵向布局变化保留且不令 AI 结果或校验失效。

## AI 语义

- 后端统一按片段边界切分区间，交集非空才相关；端点相接不算，关联不跨区间传递。每段走向均必须遵循，权重仅比较同领域笔墨侧重。
- 叠条定义参与时机、先后、关联和侧重，构成节奏骨架；本章规划在骨架上补充具体事件、冲突、动机与承接。统一上下文顺序为“节奏骨架 → 具体内容 → 写作要求”，保留整章文字编辑，不增加逐格表单。未覆盖区间可合理承接。世界硬规则、禁忌、明确禁止项须遵守；交叠不自动形成知情或因果，不把待执行意图当成事实。
- 创作前使用现有强模型检查两者的明确矛盾。`PLAN_RHYTHM_MISMATCH`（409）包含规划字段原句、元素、片段 ID、区间、走向与差异原因；客户端显示原文并提供两处定位，不修改作者内容。检查无效或无依据时返回 `PLAN_RHYTHM_CHECK_FAILED`（503）并提示重试；未填写细节、未说明先后和正常过渡不视为矛盾。相同语义在后端进程内缓存，纵向布局不影响缓存；修改规划或叠条语义后重新检查，模型调用前后均保护上下文版本。
- 规划、正文和续写仅读取目标章叠条，模型不能修改作者数据。续写保留已有正文，前段遗漏交校验提示。
- 本章校验接入完整叠条及完整正文（取消 8000 字截断），复用原文证据门禁。停用语义检查或解析失败时显示未完成，不把该状态当作已检查。
